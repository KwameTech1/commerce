# AGENTS.md

Guidance for AI agents (and humans) working in this repository.

## Overview

This is a standalone ecommerce storefront built on the Next.js App Router
(Next.js 15, React Server Components + Server Actions, Tailwind CSS v4). It was
forked from the Vercel Commerce template but **does not rely on any external
commerce backend**. All product data is a local seed, the cart is cookie-backed,
and payments are embedded via an Eversend iframe.

## Hard rules

- **Zero required environment variables.** The app must boot and function with
  no `.env`. Any new configuration must have a sensible fallback in source
  (see `lib/config.ts`). Only `SITE_NAME` and `COMPANY_NAME` are optional.
- **No Shopify / BigCommerce / etc.** Do not reintroduce anything under
  `lib/shopify/` or the `lib/type-guards.ts` envar validation from the template.
  `app/api/revalidate/` was removed; do not recreate it.
- **Do not commit secrets.** No API keys, tokens, or `.env` files.
- **Payments are never verified server-side.** The Eversend payment tag is a
  static iframe link (`lib/config.ts` → `EVERSEND_PAYMENT_TAG_URL`, overridable
  via env; the built-in default is a demo placeholder and the checkout shows a
  configuration warning while it's in use). Payment confirmation is
  customer-asserted; there is deliberately no webhook.

## Commands

| Command                       | Purpose                                   |
| ----------------------------- | ----------------------------------------- |
| `pnpm setup`                  | Install deps, clean `.next`, start dev    |
| `pnpm dev`                    | Start dev server (webpack)                |
| `pnpm build`                  | Production build — acts as the type check |
| `pnpm start`                  | Serve the production build                |
| `pnpm prettier`               | Format all files                          |
| `pnpm prettier:check`         | Verify formatting                         |
| `pnpm test`                   | Run the Vitest unit test suite            |
| `pnpm test:watch`             | Run Vitest in watch mode                  |
| `node scripts/clean-next.mjs` | Purge `.next` after a crashed server      |

**Dev-server rules (learned the hard way):**

- **Never run `pnpm build` while `pnpm dev` is running.** The build rewrites
  `.next` (CSS chunks, route manifests) that the dev server serves from —
  they corrupt each other. Stop dev first.
- **Never force-kill the dev server mid-write.** Stop it gracefully (Ctrl+C).
  If it's hung and must be killed, run `node scripts/clean-next.mjs` before
  restarting, or collection routes will 404 and pages will lose their CSS.
- If `/search/*` pages 404 or render blank after a crash: stop the server,
  run `node scripts/clean-next.mjs`, start `pnpm dev` again.

Unit tests live in `test/` (pure logic: data layer, cart, persistence, config,
search index). **After any change run `pnpm prettier` then `pnpm build`**; the
build must pass before a change is done, and run `pnpm test` when `lib/` logic
changed.

## Architecture notes

### Data layer

- Static catalog: `lib/data/*` (products, collections, pages, menus). The public
  API matches the old `lib/shopify/index.ts` exports (`getProducts`,
  `getProduct`, `getCollections`, `getCollection`, `getMenu`, `getPage`, …),
  including `cache()` tags and `cacheLife`. Exports are typed via `lib/types.ts`
  (which also defines `Order`, `User`, `Review`). Default `RELEVANCE` sort ranks
  query matches by title prefix → title → description/tags.
- Search suggestions: `lib/search-index.ts` is a **pure client-safe** module
  (no `cache()` directives) exposing `getSearchSuggestions` for the navbar
  typeahead. Import `lib/data/products` directly, never `lib/data` (index), in
  client components.
- Prices are **GHS**: `lib/data/products.ts` scales a small reference value by
  `GHS_FACTOR`; `lib/config.ts` exports `DEFAULT_CURRENCY`.
- Collection banners: optional `image` on a `CollectionSeed` (path in
  `public/collections/`) renders on the collection page and backs the homepage
  tile, falling back to the first product image when absent.
- Product images are local PNGs in `public/products/`, generated by
  `scripts/generate-product-images.mjs` (run: `node scripts/generate-product-images.mjs`).
- When adding products, provide a `rating`, `ratingCount`, and stock fields so
  reviews, facets, and the product page render correctly. `description`
  supports `descriptionHtml` (Prose rendering) and `description` (plain text).

### Cart

- `lib/cart.ts` implements a cookie cart (30-day expiry). Server actions in
  `components/cart/actions.ts` and `components/checkout/actions.ts` read/write it.
  The cart is cached with `cacheLife("days")` and invalidated via the `cart` tag
  (`TAGS.cart`). Never fetch the cookie from a client component; use the server
  actions.

### Persistence (browser-local)

- `lib/persistence/*` are **client-side** stores (localStorage) exposed through
  modules backed by `cache()`:
  - `users.ts` — register/login via **salted SHA-256** hashes stored as
    `v2:<salt>:<hash>` (async `crypto.subtle`); legacy `demo-*` hashes are
    re-hashed on first successful login. Also `updateProfile`,
    `changePassword`, and `deleteAccount` (keeps orders but detaches `userId`).
    Validation: email pattern, name ≥ 2 chars, password ≥ `MIN_PASSWORD_LENGTH`
    (8). `setCurrentUser`/`logout` dispatch the `AUTH_EVENT` window event so
    same-tab components re-sync.
  - `orders.ts` — createOrder/getOrders/getOrder/markOrderPaid (`userId` optional,
    optional `paymentRef`), `detachOrdersFromUser` (account deletion).
  - `reviews.ts` — get/add review with rating averaging.
  - `wishlist.ts` — per-user lists (`wishlist-<userId>`); signed-out visitors use
    the guest `wishlist` key, and `mergeGuestWishlist` folds the guest list into
    the account on sign-in (call it after `setCurrentUser` on login/register).
- Hydration: components that read localStorage must gate on a `useEffect`/mounted
  flag (`typeof window !== "undefined"`) to avoid SSR/client mismatch. Accounts,
  orders, and reviews are **not** shared across browsers/devices.

### Routing

- Homepage sections live in `app/page.tsx` and `components/home/`.
- Catalog browsing lives under `app/search/**`, wired with `app/search/layout.tsx`
  (category tree + facets) and `app/search/[collection]/page.tsx`. Grids render
  through `components/search/pagination.tsx` (server-side `?page=` paging, 12
  per page — no client JS required for the grid).
- Checkout: `app/checkout/page.tsx` + `components/checkout/checkout-form.tsx`
  (shipping stage → create order → Eversend iframe → confirm paid).
- Receipts: `app/confirmation/[orderId]/page.tsx` reads the order from
  localStorage (client component; not found ⇒ "Order not found" state).
- Accounts: `app/register`, `app/login`, `app/account`, `app/wishlist`.
- Toasts use sonner (already mounted in `app/layout.tsx`).

### UI conventions

- Amazon-inspired style: dark navbar, amber call-to-actions
  (`bg-amber-400`/`text-black`), category tiles, and a departments dropdown.
  Do not reintroduce blue primary buttons.
- Use Tailwind classes; new components should be server components by default and
  use `lib/data` imports (never fetch at runtime).
- Prefer local components over adding new dependencies. If a library is needed,
  confirm the pattern already imported in the repo before reaching for a new one.

## File conventions

- TypeScript strict; no unused imports; run Prettier for formatting.
- Route-level folders mirror components for cohesion
  (`components/cart`, `components/checkout`, `components/product`, …).
- Keep `lib/types.ts` as the single source of types — do not duplicate.
